The file downloader at `/app/bin/fetch-file` currently downloads a URL to an output path, but it does not safely resume interrupted downloads. Update the implementation in `/app/src/downloader.py` so repeated invocations of `/app/bin/fetch-file URL OUTPUT_PATH` can resume from `OUTPUT_PATH.part` when it is safe, using the open-ended HTTP header `Range: bytes=<partial_size>-` and `If-Range` with the previously observed `ETag`.

A completed download must atomically produce `OUTPUT_PATH` with exactly the bytes served by the current resource. The downloader should compare the received body length with `Content-Length`; a mismatch should leave the partial data in `OUTPUT_PATH.part`, exit with a failure status, and avoid creating `OUTPUT_PATH`. Partial state should be kept in `OUTPUT_PATH.part` and `OUTPUT_PATH.part.meta`; if the server ignores `Range`, changes `ETag`, or the local metadata is missing or inconsistent, the downloader must restart from byte 0 rather than appending incompatible bytes. If a ranged request receives `416 Range Not Satisfiable`, the downloader may finalize the partial file only when headers and local metadata show that `OUTPUT_PATH.part` already has the complete current resource; otherwise it must restart from byte 0. If `OUTPUT_PATH` already exists and the server confirms through headers that it is already complete for the current resource, the command must exit successfully without downloading the response body again.
