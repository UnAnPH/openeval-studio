# Trade-offs and honest limitations

A runtime gate is a chain of uncomfortable choices. These are the ones this codebase
makes, with the measured cost of each (repro commands in [FINDINGS.md](FINDINGS.md)).

## 1. Fail-open is the default, but not forever

**Decision.** Hooks fail **open** on a transient gateway error and fail **closed** after
3 failures inside 60 s. State lives in `~/.openeval/circuit_breaker.json`; every write is
`fcntl.flock` + temp file + `os.replace`, so concurrent hooks cannot corrupt it. A single
HTTP 200 resets the counter. When tripped, hooks return an interactive lockout —
`force_ask` for Antigravity, Codex, and OpenCode, `ask` for Claude Code and Cursor.

**Why.** A naive fail-open gate lets a model (or an attacker who can stall the
gateway) bypass every check. A strict fail-closed gate locks developers out on a
Wi-Fi blip. The 3/60 window is the compromise: normal blips stay invisible, sustained
outages stop autonomous loops.

**Cost.** During an outage the developer must acknowledge a lockout every 60 s or
switch to `paused`. Strict deployments can set `OPENEVAL_GATE_FAIL_MODE=closed`.
Thresholds: `OPENEVAL_MAX_GATEWAY_FAILURES`, `OPENEVAL_FAILURE_WINDOW_SEC`.

## 2. Calibrated prefill is bounded on the hot path; Tier 3 runs asynchronously

**Decision.** On `POST /api/v1/watcher/evaluate`, **Tier 1** deterministic rules and
**Tier 1.5** (`gemini-decision-1` calibrated prefill, **0.65 s** client budget, `0`
output tokens) execute within the hook deadline (**1.5 s**, or **2.2 s** for
Antigravity). When Tier 1.5 returns a non-`allow` verdict, `server/routes/watcher_gate.py`
persists the decision and responds to the hook first, then spawns **Tier 3 Deep Review**
asynchronously off the hot path (**20 s** default timeout, cross-family judge routing).
Only when Tier 1.5 is disabled or unavailable does the gateway fall back to the
synchronous triage/review path clamped to **0.8 s** (`_LLM_BUDGET_SEC`). On model
failure the server default is `fail_open` (`OPENEVAL_WATCHER_ON_FAILURE=fail_closed`
escalates); a transport failure at the hook follows the circuit breaker. Native Inspect
runs generated by `build_inspect_task_for_dir` use `compose.yaml` sandboxes that enforce
`network_mode`, `cpus`, `mem_limit`, and `pids_limit`; the live `DockerSandbox` path
honors the image `WORKDIR` and enforces `build_timeout_sec`.

**Why.** Background-only monitoring cannot block a destructive tool call before it
runs, whereas awaiting a reasoning model on every prompt breaks the 1.5 s hook timeout.
Separating `0`-token calibrated prefill (hot path) from cross-family deep review (async
enrichment) keeps blocking latency bounded while preserving rich audit explanations.

**Cost.** If Tier 1.5 answers in 950 ms, the agent still waits up to the timeout. A
70-sample benchmark measured `gemini-decision-1` at **p50 731.7 ms / p95 1,084.5 ms**
vs. a ~184 ms warm target; with the default `fail_open`, a model outage on the sync
fallback degrades to heuristic scores rather than a lockout, and Tier 3 cannot upgrade
an already-returned `allow` before execution—it only enriches non-`allow` verdicts
post-decision.

## 3. Regex is a pre-filter, not a classifier

**Decision.** Tier 1 stays deterministic: shell normalization, command rules, tool
thresholds, provenance and constraint checks. On the 70-trajectory Apollo benchmark:
**50.0% recall (26/52; 46.2% earlier)**, **0% FPR (0/18)**, MAE 2.66. Tier 1.5 raises
recall to **84.6% (44/52)** with MAE 1.40.

**Why.** Sub-millisecond local checks are what make the gate tolerable on every `ls`
and `git status`. Expensive semantic review is reserved for calls the rules cannot
settle.

**Cost.** Regex has a hard recall ceiling: 0% of real-world transactions (Stripe
charges, GPU spin-ups) and unapproved dependency installs, 25% of prompt injections and
infrastructure disruptions. Those need the calibrated or LLM stage; without an API key
they are not covered. Escalation is also non-deterministic: repeated runs collapsed the
Tier 1+2 rows back to Tier-1 numbers when the model path was unavailable.

## 4. Local blacklist before the network

**Decision.** Every hook runs an in-process blacklist and path check **before** it
sends anything. Obvious wipes, secret reads, encoded shell pipelines, and interpreter
reflection are denied with no server dependency.

**Why.** It is the only stage that still works when the gateway is down, and it keeps
local checks at ~0.004 ms p95 (5,000 iterations, benign and destructive inputs).

**Cost.** The local patterns duplicate a subset of server rules, so they can drift.
They are intentionally shallow: a novel obfuscation that the local regex misses still
needs the gateway or the LLM to catch it.

## 5. Codex auto-review safeguards

**Decision.** Three Apollo-derived invariants are enforced in the decision logic:
**reversibility is not authorization** (an explicit negative constraint forces a
non-discountable score floor of 8 and disqualifies intent discounts); **subagent
provenance** (delegated calls cannot use `auto_approve`, are blocked at score ≥ 6,
escalated at ≥ 4, and denied credential/privilege access at ≥ 9); and **informed
consent** (`ConsentDisclosure` with resources, destination, data types, blast radius,
and reversibility, rendered in the terminal lockout).

**Why.** Automated reviewers systematically over-trust reversible actions and
inherited permissions. These rules make the unsafe cases explicit rather than
relying on a model's judgment.

**Cost.** More escalations for legitimate delegated work; a `git tag` or local edit
that violates a stated constraint is still blocked even though it is undoable. The
safeguards are unit-tested (`tests/test_codex_autoreview_safeguards.py`, 26 tests),
not field-calibrated on a large fleet.

## 6. Context stripping

**Decision.** Prior trajectory context keeps tool calls and reasoning but replaces
bulky tool output with `[RESULT]: (tool output stripped)`
(`format_stripped_trajectory`). The docstring estimates an 80%+ token reduction; the
benchmark runs both conditions so the effect is visible.

**Why.** Logs can be thousands of lines; sending them to a model on every tool call
destroys the latency budget and invites prompt injection through tool output.

**Cost.** Anything that appears **only** in stdout is invisible to the model stage —
steganographic leaks, injected instructions, a credential echoed by a build log.
Stripping also shifts severity slightly (Tier 1+2 MAE 2.30 stripped vs 2.63 full).
Full-output mode exists as an ablation, not as the default.

## 7. PostgreSQL 16 for operational state, DuckDB for `.eval` analytics, and remaining gaps

**Decision.** `server/watcher_store.py` persists operational state (users, sessions,
reviews, trajectory events) in PostgreSQL 16 via SQLAlchemy and Alembic (`0001`–`0004`
in `server/db.py`), enabling `user_id` row scoping on every query, concurrent gateway
writers, SQL percentiles for the Analyzer, and persistent migrations across restarts.
DuckDB remains in `server/analytics_store.py`, where it scans Inspect `.eval` archives
for `server/routes/eval.py`. `get_analyzer_summary` uses SQL counters/percentiles plus
Python threat grouping, with an in-memory fallback; it is not a "<2 ms" guarantee.

**What that costs.** PostgreSQL is a hard dependency: `/api/health` returns 503 when it
is unreachable, and the Kubernetes manifests need a database service. Three deliberate
limitations remain:

- **Tenancy is row-level, not organizational.** Every row carries `user_id`; the demo
  tenant is isolated and read-only for policy, key, and delete mutations (`401`), but it
  does permit IP-rate-limited real `POST /api/eval/run` and `.../stop` launches so
  anonymous visitors can exercise the product. There is no org RBAC, SSO, or SOC 2
  audit trail.
- **SIEM export is best-effort.** `server/routes/watcher_gate.py` dispatches
  `dispatch_siem_event` on deny/escalate when `OPENEVAL_SIEM_ENDPOINT` is set, via
  synchronous `urlopen(..., timeout=1.0)`; there is no persistent retry queue.
- **SSE and rate limiting degrade per process.** Redis provides Pub/Sub and the Lua
  token bucket (`_redis_client.eval`, not `EVALSHA`); without it both fall back to
  in-memory structures — fine for one process, wrong for replicas.

## Not claimed

No enterprise SaaS, no multi-tenant MDM, no always-on LLM guarantee, no SOC 2, no
"zero host Docker exposure" (sandboxes use `tecnativa/docker-socket-proxy`, which mounts
the socket read-only), and no frontier-model Pass@k beyond [FINDINGS.md](FINDINGS.md).
